# PI-4A UX-to-Contract Mapping

Baseline: `18cfac0cbf9ba54306ddd66415a7f00baafb70b4`

Status meanings:

- `SUPPORTED`: the current contract directly supports the UX.
- `SUPPORTED_WITH_MAPPING`: supported through an explicit UI/domain projection.
- `PARTIAL`: some required behavior exists; unsupported behavior must be disabled or disclosed.
- `NOT_IMPLEMENTED`: no current contract may be presented as functional.
- `UNKNOWN`: source inspection could not determine support.

## 3. UI-to-domain state mapping

| PI-4A UI  | Domain evidence                                                                        | Invalidating event                   |
| --------- | -------------------------------------------------------------------------------------- | ------------------------------------ |
| AI_DRAFT  | generated current version with generation provenance and no accepted user edit lineage | first accepted edit                  |
| EDITED    | current DRAFT version/revision with human edit lineage                                 | current-version validation completes |
| VALIDATED | current-version run is PASS or acknowledged WARNING                                    | any new current version/edit         |
| FINAL     | current-version ApprovalRequest is APPROVED and references current validation          | edit creates a new version           |

Domain `ERROR` maps to user-visible validation `FAIL`. Domain validation execution `FAILED` maps to `Validation could not run` and never to a rule failure.

## 4. Blocking assessment

No source contradiction prevents a coherent PI-4A target freeze. Project persistence and Project-local Assets are material backend gaps, but the target hierarchy, ownership semantics, disabled-state treatment, and required future contract are unambiguous. They are therefore recorded as **non-blocking for PI-4A documentation** and blocking for any PI-4C implementation that attempts those mutations without a separate backend decision.

The specification does not authorize a Project schema/API change.
